# GA4データ保存ルール

このファイルは、毎月のGA4データをどう保存・整理するかのルールをまとめたものです。
2026年5月から運用開始。

## 結論（保存物の分担）

| 種類 | 形式 | 保存先 | 用途 |
|---|---|---|---|
| 上位40〜50位のスナップショット | **PDF** | Google Drive | スクショ的な証拠保管 |
| 全件（〜数百件） | **CSV** | Google Drive | 分析の元データ |
| 月次サマリー | **Markdown** | このリポジトリ (`docs/analytics/YYYY-MM/`) | 振り返り・履歴 |

## なぜCSV中心にするのか

CSVは PDF と違って次のような分析が一気にできるので、月次分析が積み上がるほど価値が出ます。

- **前月比較**：先月のCSVと今月のCSVを突合して順位・PV増減を一覧化
- **有料LP分析**：`title CONTAINS "資料セット" OR "PowerPoint"` でフィルタしてPV合計を出す
- **404抽出**：`title = "404"` や `"素材が見つかりません"` の発生をトラッキング
- **カテゴリ比較**：「下肢」「上肢」「体幹」など部位別のPV推移
- **単体素材 vs 一覧**：単体素材のロングテールが伸びているか確認

PDFだけだと「目視で読むしかない」ので、毎月どんどん溜まっていくと振り返りが現実的でなくなります。CSVで残しておけば、年末のまとめでも、四半期での施策判断でも、すぐに過去データを引けます。

## なぜ Notion には貼らないのか

- 200件超のテーブルをそのまま Notion に貼ると重い・検索しづらい
- 表記揺れの修正やフィルタの再実行が Notion では手間
- 月次のメモは Markdown のほうが軽く、git で diff を残せる
- 必要なら Notion には「サマリーへのリンクだけ」を置く形にする

## Google Drive のフォルダ構成

```
自主トレ素材庫/
└── 01_アクセス解析/
    └── GA4/
        ├── 2026/
        │   ├── 2026-04/
        │   │   ├── 2026-04_GA4_ページとスクリーン_上位50.pdf
        │   │   └── 2026-04_GA4_ページとスクリーン_全XXX件.csv
        │   ├── 2026-05/
        │   │   ├── 2026-05_GA4_ページとスクリーン_上位50.pdf
        │   │   └── 2026-05_GA4_ページとスクリーン_全224件.csv
        │   ├── 2026-06/
        │   └── ...
        └── 2027/
```

ファイル名の命名規則：

```
YYYY-MM_GA4_<レポート種別>_<範囲>.<拡張子>
```

例：
- `2026-05_GA4_ページとスクリーン_上位50.pdf`
- `2026-05_GA4_ページとスクリーン_全224件.csv`
- `2026-05_GA4_集客_デバイス別.csv`（将来的にレポート種別が増えたら）

## このリポジトリに置くもの

`docs/analytics/YYYY-MM/` に以下の4ファイルだけを置きます。

| ファイル | 内容 |
|---|---|
| `README.md` | このフォルダの説明 |
| `summary.md` | 全体指標と所感、次月以降の確認ポイント |
| `pages-top50.md` | 上位50ページの記録（手元検索用） |
| `ga4-export-note.md` | このファイル（保存ルール）。基本毎月コピペでOK |

## 月初の運用フロー

1. **GA4でPDFをエクスポート**（ページとスクリーン、上位50件まで）
2. **GA4でCSVをエクスポート**（全件）
3. Google Drive の `01_アクセス解析/GA4/YYYY/YYYY-MM/` に両方アップロード
4. `docs/analytics/_template/` をコピーして `YYYY-MM/` を作る
5. `YYYY-MM/summary.md` と `pages-top50.md` を書く
6. `docs/analytics/README.md` のテーブルに月のリンクを1行追加
7. git commit & push

## 取り扱い注意

- GA4の個人情報・IPアドレスはエクスポートに含まれないので、Driveへのアップロードは通常運用でOK
- ただし「ユーザー単位の探索レポート」を出した場合は個人特定リスクがゼロではないので、Driveに置く際は社外共有しないこと
- このリポジトリ（GitHub）に**CSV本体は置かない**。リポジトリには集計・サマリーだけ
